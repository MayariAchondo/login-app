# Login App — Evaluación 1

App móvil desarrollada con React Native, Expo y TypeScript que implementa un flujo de login con validación en memoria, navegación entre pantallas con Expo Router y comunicación de datos entre rutas.

## Pantallas

- **Login** (`app/index.tsx`): Formulario con email y contraseña. Valida credenciales en memoria y muestra mensaje de error si son incorrectas.
- **Home** (`app/(tabs)/index.tsx`): Pantalla de bienvenida tras login exitoso.
- **Perfil** (`app/(tabs)/profile.tsx`): Muestra el email ingresado en el login.

## Instalación y uso

1. Clona el repositorio:
git clone <URL_DEL_REPOSITORIO>

2. Entra a la carpeta:
cd login-app

3. Instala las dependencias:
yarn install

4. Inicia el servidor:
yarn start

5. Presiona `a` para abrir en emulador Android.

## Problemas encontrados y soluciones

**Yarn bloqueado por Windows**
Windows restringe por defecto la ejecución de scripts externos. La solución fue autorizar explícitamente esta capacidad mediante la política de ejecución de PowerShell (`RemoteSigned`), permitiendo que herramientas instaladas globalmente como Yarn pudieran ejecutarse.

**Incompatibilidad entre Yarn 4 y rutas largas en Windows**
Yarn 4 genera una estructura de archivos con rutas extremadamente largas que Windows no puede manejar, lo que impedía incluso eliminar la carpeta del proyecto. La solución fue revertir a Yarn 1 (classic), versión más compatible con el sistema de archivos de Windows.

**Plantilla incorrecta y estructura de carpetas ausente**
El proyecto fue creado inicialmente con una plantilla simple que no incluía Expo Router. Fue necesario recrear el proyecto con la plantilla correcta y luego ejecutar el script `reset-project` para limpiar el contenido de demostración y trabajar sobre una base real.

**El emulador Android no conectaba con el servidor**
La comunicación entre el servidor de Expo y el emulador requiere que ambos estén completamente inicializados antes de intentar la conexión. La solución fue respetar el orden: primero levantar el emulador hasta que cargue completamente, luego iniciar el servidor.

**El parámetro email no llegaba a la pantalla Perfil**
Los parámetros de navegación en Expo Router deben enviarse a la ruta exacta donde serán leídos. Enviarlos a una ruta padre (`/(tabs)`) no los propaga automáticamente a las rutas hijas. La solución fue navegar directamente a `/(tabs)/profile`.
